# 一、已验证缺陷

## BUG-001 统计卡按当前页计数，未统计全部任务

| 字段 | 内容 |
|------|------|
| 环境 | 同上；生产任务控制台列表页 |
| 严重程度 | 严重（P0） |
| 复现频率 | 必现 |
| 模块 | 任务列表 / 统计卡 |

**前置条件：** 总任务数大于每页条数（例如共 9 条、分页 1/2）。状态为全部、未勾选「只看我的」。

**复现步骤：**  
1. 进入任务列表，读取五张统计卡数量并求和。  
2. 读取「N 条记录」与当前页列表状态分布。  
3. 翻至第 2 页或不翻页，对比统计卡是否只反映当前页。

**实际结果：** 统计卡之和等于当前页条数（如 5），与全量 9 不一致；与当前页状态分布一致，其他页未计入。

**预期结果：** 统计卡表示全部任务各状态数量，与记录总数一致，且不随当前页变化。

**证据：** `bug记录.docx` / BUG-001 截图。

**规则依据：** 顶部状态统计表示全部任务数量，不随分页或筛选改变。

## BUG-002 任务领取缺少唯一性约束（多用户并发与重复领取均可成功）

| 字段 | 内容 |
|------|------|
| 环境 | JMeter / 接口；制作人账号 |
| 严重程度 | 严重（P0） |
| 复现频率 | 必现（并发或重复领取条件） |
| 模块 | 任务领取 |
| 前后端定位 | 后端（无并发控制，且未校验「仅 PENDING 未分配可领一次」） |

**前置条件：** 准备 PENDING 任务；可用 JMeter。以下两场景均可复现，属同一根因。

**复现步骤：**  
1. **场景 A（多用户并发）：** 两制作人（如 `producer-chen` / `producer-lin`）同时领取同一 PENDING 任务；查看双方响应与 `assigneeId`。  
2. **场景 B（重复/同用户多次领取）：** 对同一任务并发或连续多次发起领取（含已领取后再领）；查看是否多次成功。  
3. 刷新详情，确认最终负责人是否唯一、是否被后请求覆盖。

**实际结果：**  
- 场景 A：两用户均领取成功，且 `assigneeId` 不同。  
- 场景 B：同一任务多次领取仍返回成功。

**预期结果：** 同一任务无论多用户并发还是重复领取，有且仅有一次成功；其余失败；最终负责人唯一。

**证据：** `bug记录.docx` / BUG-002（含多用户并发与重复领取两组截图）。

**断言说明：** 不能只看 HTTP 200；须排除「两个调用方都误以为成功」。

**规则依据：** 并发领取同一任务只能有一名制作人成功；已被领取的任务不能再次领取。

## BUG-003 审核通过时填写的审核意见未提交保存

| 字段 | 内容 |
|------|------|
| 环境 | 浏览器 + Network；审核工作台 |
| 严重程度 | 一般（P1） |
| 复现频率 | 必现 |
| 模块 | 审核工作台 |

**前置条件：** 存在待审核任务；审核意见输入框可编辑。

**复现步骤：**  
1. 填写非空审核意见。  
2. 点击通过。  
3. 查看 `review` 请求体；通过后查看详情是否展示意见。

**实际结果：** 请求体仅为 `{"decision":"APPROVE"}`，未带意见字段；意见未保存。

**预期结果：** 页面提供意见输入时，通过应提交并落库可追溯；或明确不落库并去掉输入。

**证据：** `bug记录.docx` / BUG-003 截图。

## BUG-004 预置任务歌词不足 20 字符，却能进待审核/被通过

| 字段 | 内容 |
|------|------|
| 环境 | 重置后的预置数据；任务如「未读消息」 |
| 严重程度 | 严重（P0） |
| 复现频率 | 必现（预置数据） |
| 模块 | 测试数据 / 业务约束 |

**前置条件：** 使用系统预置或重置后的初始数据。

**复现步骤：**  
1. 打开预置待审核/已通过任务，查看歌词与字符数（如 19 字符）。  
2. 对照：自行将歌词改短再提交，确认正常操作路径存在长度限制。  
3. 观察该预置任务是否仍可审核通过。

**实际结果：** 预置歌词不足 20 字，却处于待审核并可被通过；用户自行修改提交时有限制。

**预期结果：** 预置数据也应满足去空白后 ≥20 字，不应存在违规存量任务。

**证据：** `bug记录.docx` / BUG-004 截图。

**归类：** 预置/种子数据问题（偏后端初始化），非前端字数显示算错。

**规则依据：** 歌词去除首尾空白后至少 20 个字符。

## BUG-005 待审核态提示误导（本人已是负责人仍提示切换负责人）

| 字段 | 内容 |
|------|------|
| 环境 | 制作人林晓；任务「未读消息」待审核 |
| 严重程度 | 一般（P1） |
| 复现频率 | 必现 |
| 模块 | 制作内容 / 提示文案 |

**前置条件：** 当前身份对应用户为负责人林晓；任务状态为待审核。

**复现步骤：**  
1. 打开详情，确认页头负责人为「林晓」。  
2. 查看制作内容区底部权限提示。

**实际结果：** 提示「当前身份无编辑权限，请切换至任务负责人。」

**预期结果：** 应说明因待审核不可编辑；不应暗示当前用户不是负责人。

**证据：** `bug记录.docx` / BUG-005 截图。

## BUG-006 同一待审核任务并发审核出现多个决定成功

| 字段 | 内容 |
|------|------|
| 环境 | JMeter；同一待审核任务；APPROVE 与 REJECT 同时发送 |
| 严重程度 | 严重（P0） |
| 复现频率 | 必现（并发条件） |
| 模块 | 审核 / 并发 |

**前置条件：** 任务处于 IN_REVIEW；两路合法审核请求；同步定时器制造同时到达。

**复现步骤：**  
1. 一路 `APPROVE`，一路 `REJECT`（驳回原因 ≥8 字）。  
2. 同时发送，查看两请求结果与任务最终状态。

**实际结果：** 两路请求均成功。

**预期结果：** 仅一个决定成功，另一请求明确失败；最终状态唯一。

**证据：** `bug记录.docx` / BUG-006 截图。

**规则依据：** 同一待审核任务并发审核只能有一个决定成功。

## BUG-008 直接提交审核时歌词/音频未保存，须先保存草稿再提交

| 字段 | 内容 |
|------|------|
| 环境 | 制作中任务详情；Network 查看 submit |
| 严重程度 | 严重（P0） |
| 复现频率 | 必现 |
| 模块 | 提交审核 / 交付内容 |

**前置条件：** 当前用户为任务负责人；任务为制作中。

**复现步骤：**  
1. 填写合法歌词（≥20）与 https 音频，**不点保存草稿**，直接点提交审核。  
2. 查看是否提示已提交、状态是否变为待审核。  
3. 查看 submit 请求负载、响应体、详情制作区。  
4. 对照：先点保存草稿，再提交，查看内容是否保留。

**实际结果：**  
- 直接提交：负载中可有歌词/音频，状态可变待审核，但响应无内容、详情为空（未落库）。  
- 先保存再提交：内容可正常保存。

**预期结果：** 提交审核应保存当前编辑区内容并进入 IN_REVIEW，无需强制先点保存草稿。

**证据：** 直接提交的请求负载（有数据）+ 响应/详情为空；先保存再提交成功的对照截图（见 `bug记录.docx` / BUG-008，若已附）。

**规则依据：** 提交成功后，当前歌词和音频应一起保存，任务进入 IN_REVIEW。
