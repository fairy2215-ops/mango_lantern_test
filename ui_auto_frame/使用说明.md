# UI 自动化框架使用说明

基于 **Pytest + Selenium + Excel 关键字驱动 + Allure**，用例写在 Excel 里即可驱动执行。

---

## 1. 环境准备

- Python 3.x、Chrome / Edge 浏览器
- 安装依赖：`pytest`、`selenium`、`openpyxl`、`allure-pytest`、`jinja2` 等
- 本机已配置 Allure 命令行
- 驱动放在 `driver/`，路径在 `config/config.py` 中配置
- 被测前端已启动（示例：`http://localhost:5173/tasks`）

---

## 2. 目录说明

| 目录/文件 | 作用 |
|-----------|------|
| `config/config.py` | 浏览器、用例文件、数据库等配置 |
| `data/` | Excel 测试用例 |
| `core/` | 操作关键字、断言关键字、业务关键字 |
| `testcases/test_runner.py` | 读取用例并逐步执行 |
| `utils/` | Excel 读取、驱动管理、日志/报告工具 |
| `run.py` | 一键执行并生成/打开 Allure 报告 |
| `report/` | Allure 报告输出 |
| `log/`、`screenshot/` | 日志与失败截图 |

---

## 3. 配置说明

编辑 `config/config.py`：

```python
BROWSER_TYPE = "chrome"          # chrome / edge
DRIVER_TYPE = "local"            # local / remote
HEADLESS = False
EXCEL_FILE = "./data/音乐任务管理平台_关键字用例.xlsx"
MULTI_PROCESS = False            # True 开启多进程
```

切换项目时，主要改 `EXCEL_FILE` 和浏览器配置即可。

---

## 4. 用例编写（Excel）

文件第 1 行为中文表头，第 2 行为英文字段，第 3 行起写用例。

| 字段 | 说明 |
|------|------|
| id | 用例编号；同一用例后续步骤 id 留空 |
| feature / story / title | 模块、场景、标题（进 Allure） |
| step_num / step_name | 步骤序号、步骤描述 |
| keyword | 关键字名，如 `open`、`click`、`input` |
| by / value | 定位方式与表达式，如 `xpath` + `//button[...]` |
| data | 输入数据、URL、等待秒数等 |
| index | 一组元素时取第几个；单个元素留空 |
| is_true | 是否执行，填 `True` |

**规则简述：**

1. 新用例：写齐 id、模块、场景、标题 + 第 1 步  
2. 同用例后续步骤：只写步骤相关列，id 等留空  
3. `is_true=True` 的用例才会跑  

**示例：**

| id | feature | story | title | step_num | step_name | keyword | by | value | data | is_true |
|----|---------|-------|-------|----------|-----------|---------|----|-------|------|---------|
| mtm_scn_0001 | 业务场景 | 制作人领取与制作提交 | 制作人主路径... | 1 | 打开页面 | open | | | http://localhost:5173/tasks | True |
| | | | | 2 | 重置数据 | click | xpath | //button[contains(.,'重置数据')] | | |
| | | | | 3 | 断言提示 | assert_text | xpath | //*[contains(text(),'...')] | 预期文案 | |

---

## 5. 常用关键字

**操作：** `open` / `click` / `input` / `clear` / `wait` / `shot` / `select_by_text` / `refresh` / `back` / `upload` / `switch_to_frame` 等  

**断言：** `assert_url` / `assert_title` / `assert_text` / `assert_element_exist` / `assert_alert_text`  

**业务：** `login`（账号密码登录）、`get_attribute`（提取属性供后续步骤用 `{{变量}}`）

`shot` 会先等页面加载完成，再默认停留 1.5 秒后截图；`data` 可填等待秒数。

---

## 6. 执行与报告

```bash
python run.py
```

流程：执行用例 → 生成 Allure 报告 → 自动打开浏览器查看。

- 报告目录：`report/test/html_report`
- 日志：`log/test.log`
- 失败时自动截图到 `screenshot/`

单独跑用例也可：

```bash
pytest -vs ./testcases/test_runner.py
```

## 7. 当前业务用例

文件：`data/音乐任务管理平台_关键字用例.xlsx`  

覆盖主流程：

1. 制作人领取 → 编辑 → 提交审核  
2. 驳回后再修改提交  
3. 审核员通过  
4. 审核员驳回  

每条用例开头会「重置数据」，保证数据可重复执行。
